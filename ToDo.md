* zLib: data that does not end with pipe is not compressed and stays in flush buffer until next write, also timer flush can not send it, see "Missing ending pipe in compress data" in cAsyncConn::Write()
* System info: MySQL/MariaDB memory usage is found with ps and pgrep, which Windows does not have, find database server process another way, for example by pid_file server variable when database runs on same machine, see cInfoServer::SystemInfo()
* Commands: move management of shell scripts into verlihub executable as command line options, in own source file for all supported commands, so it works same on Linux and Windows and shell scripts can be removed later: install (configuration folder, dbconfig, tables, master user), adduser, getconf, setconf, version, run, stop, restart, reload (Windows has no SIGHUP, needs named event or similar), status, backup and restore (mysqldump), geoip, autoload, uphelp, modport, clean, daemon (keep hub running), multiple hubs (vhm), skip migration, regimporter and gui, they are dead
* Windows: cTime::operator long() returns microseconds as long, which is 32 bit on Windows, so it overflows, also tv_sec of timeval is 32 bit there (year 2038), no explicit use found, change it carefully because implicit conversions of cTime can become ambiguous
* Windows W6: portable folder with DLLs and their license texts next to exe, paths relative to exe, default configuration folder and install prefix, first run setup, locale names like en-US
* Windows W7: run as Windows service, CI that builds Windows zip
* IPv6: Verlihub has no IPv6 support yet, when it is added, also db_host in dbconfig needs [address]:port form
* MySQL: MYSQL_OPT_RECONNECT is deprecated and will be removed, it gives warning on connect, only main connection uses it (cMySQL::Connect), replace it with own reconnect when connection is lost (CR_SERVER_GONE_ERROR, CR_SERVER_LOST) in cQuery, like cMySQLWorker::Execute already does on its own thread, main connection runs on main thread, so reconnect there must not wait long, and charset must be set again after reconnect
